# Lexie 手機版與電腦版並存設計

日期：2026-08-11

## 背景

目前 GitHub Pages 已部署電腦操作版與電腦結果版，但電腦版曾取代原本的手機操作版。這次修正要讓手機版與電腦版同時存在，各自有操作頁與結果頁，並保留已公開分享的電腦版網址。

## 目標

- 同一個 GitHub Pages 網站提供四個可獨立開啟的頁面。
- 完整還原原始手機操作版，不以響應式電腦版代替。
- 製作與手機操作版一致的手機結果頁，保留電腦結果頁的內容證據。
- 保留現有電腦版網址，避免既有連結失效。
- 首頁清楚區分裝置版本與「操作／結果」用途。

## 非目標

- 不新增登入、雲端同步、後端資料庫或正式志工審閱系統。
- 不改寫四個頁面的教學內容與範例資料。
- 不讓手機與電腦版本共用同一個自動切換頁面。

## 公開頁面與路由

| 用途 | 路徑 | 來源或處理方式 |
| --- | --- | --- |
| 版本選擇首頁 | `/` | 更新現有 `index.html` |
| 手機操作版 | `/mobile-demo.html` | 從提交 `8a2ed93` 完整還原原始手機頁 |
| 手機結果版 | `/mobile-result.html` | 以現有結果內容製作最大寬度 480px 的單欄手機頁 |
| 電腦操作版 | `/demo.html` | 保留現有頁面與網址 |
| 電腦結果版 | `/result.html` | 保留現有頁面與網址 |

## 首頁設計

首頁分成兩個主要區塊：

1. 「手機版」：提供「開始操作」與「查看結果」兩個入口。
2. 「電腦版」：提供「開始操作」與「查看結果」兩個入口。

每個入口要直接說明用途，避免把結果範例誤認為另一個產品版本。首頁維持現有白底、藍色重點與簡潔卡片語言。

## 手機版設計

手機操作版沿用原始 480px 內的 `.shell` 版型、觸控按鈕、七關流程與瀏覽器 `localStorage`。手機結果版使用相同的 480px 內容寬度、手機頂列、單欄區塊與可橫向捲動的段落導覽；結果內容、七關紀錄、文章與志工回饋均與電腦結果版一致。

手機結果版是獨立 HTML，不依賴電腦版 CSS，也不會因電腦版後續調整而改變版面。

## 電腦版設計

`demo.html` 與 `result.html` 保持目前寬版配置、內容和互動，不更名、不移除。這能保留已分享的公開網址並降低回歸風險。

## 資料與相容性

- 手機操作版繼續只把輸入內容存放在使用者自己的瀏覽器。
- 電腦操作版沿用目前的本機儲存方式。
- 四頁皆為靜態 HTML，可直接由 GitHub Pages 發布。
- 不刪除現有頁面；Git 歷史保留所有舊版本。

## 驗證標準

- 四個公開網址皆回應 HTTP 200。
- 首頁四個入口均指向正確且存在的頁面。
- 手機操作版的 JavaScript 可解析，開始按鈕與七關流程標記存在。
- 手機結果版包含書籍、七關、組裝、文章與志工回饋五個內容區塊。
- 電腦操作版與電腦結果版的檔案雜湊在本次修改中維持不變。
- GitHub Pages 最新建置狀態為 `built`，提交 SHA 與本次部署一致。
- 公開下載的四個頁面與儲存庫檔案雜湊一致。

## 失敗處理

- 若原始手機操作版無法從 Git 歷史還原，停止部署並回報，不以電腦版縮窄冒充。
- 若 GitHub Pages 建置失敗，保留已推送提交、讀取建置錯誤並修正後重新驗證。
- 若公開網址仍回傳舊快取，等待 Pages 完成並以檔案雜湊確認實際版本，不提前宣告完成。
